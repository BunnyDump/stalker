# X-Ray UI Editor 1.2

Автономный редактор развёрстки UI для S.T.A.L.K.E.R. / X-Ray. Интерфейс на русском. Редактирует игровые XML и области texture id; DDS служат исходными текстурами и не перезаписываются.


## Что изменилось в 1.2

- Кнопки «Назад / Вперёд» и Alt+← / Alt+→ возвращают к предыдущему XML вместе с масштабом, положением холста, выделением и вкладкой. Переход к атласу больше не заставляет заново искать исходный элемент. Состояние хранится в текущем сеансе проекта.
- Под холстом появилась панель выделения с быстрым переходом к атласу и исходному тегу, а также меню «Расположить».
- Правая кнопка открывает контекстное меню: выбор перекрывающихся элементов, дубликат, удаление, скрытие, блокировка и восстановление видимости. Для группы доступны все четыре края, центры, одинаковая ширина / высота / размер и равные интервалы по X / Y. Ориентир — первый выбранный независимый элемент; заблокированные и скрытые пропускаются. Распределение требует минимум трёх элементов и оставляет крайние на месте. При нехватке места интервалы могут быть отрицательными: редактор не расширяет крайние границы автоматически.
- Команды группы учитывают разные родители координат и сохраняются одним шагом отмены. «Вписать выделение» теперь показывает всю группу.
- В XML добавлены номера строк и поиск Ctrl+F, F3 / Shift+F3, учёт регистра, число совпадений и переход с конца к началу. Поиск буквальный, без регулярных выражений; счётчик ограничен «10000+», переходы продолжают работать по всему тексту.
- Исправлены повтор правки после отмены до исходного текста, переход к тегу в файлах с CRLF и сохранение Windows-переносов строк при ручной правке.
- Развёрнутые и свёрнутые ветви дерева сохраняются после правок. Поисковые фильтры обновляются после короткой паузы ввода; списки сохраняют выбранную строку. Кнопки сохранения и истории показывают доступность действия.
- Исправлены повторное декодирование XML-сущностей и пустые значения атрибутов без кавычек. Относительные пути текстур различаются по XML-владельцу. Проверка UV обходит вложенные `<file>` и сообщает о повреждённых изображениях без прерывания всего отчёта.

## Что изменилось в 1.1

- Семь тем: «Текущая», «Системная», «Тёмная», «Светлая», S.T.A.L.K.E.R. ТЧ, ЧН и ЗП. Темы игры используют собственные палитры по мотивам трилогии: олива и янтарь, холодная сталь и бирюза, зелёный экран КПК. Меню выбора расположено справа в главном меню. Тема сохраняется сразу и восстанавливается при запуске; системная использует цвета Windows и реагирует на их изменение.
- Новая многомасштабная иконка встроена в EXE и окно; отдельный app.ico лежит в архиве.
- Изменяемая ширина боковых панелей, F11 для работы только с холстом, разделение инспектора на геометрию, текстуру и атрибуты. Числовые поля X/Y/W/H вынесены отдельно.
- Инструмент «Рамкой» выделяет полностью попавшие в рамку элементы. Ctrl+A выделяет видимые разблокированные элементы на холсте; Delete удаляет выделенные. При выборе текста эти сочетания сохраняют обычное значение.
- Просмотр текстуры крупным фрагментом либо полным атласом. Четыре состояния кнопок: обычное, наведение, нажатие и недоступное. Поддержаны r/g/b/a в теге texture и отражение. Это режимы просмотра; они не перекрашивают DDS и не меняют XML.
- Поиск использований texture id в текущем варианте проекта с переходом к элементу.
- F5 перечитывает DDS с диска, включая заменённые файлы. Кэш путей, изображений и ошибок предотвращает повторную загрузку при каждой перерисовке. Повторяющиеся texture id показываются в диагностике; используется первое определение в порядке имён файлов.
- Исправлено уменьшение рамки через противоположную грань: фиксированная грань не смещается. Потеря захвата мыши отменяет незавершённый жест. Неприменённая правка XML блокирует изменения холстом, чтобы не смешивать две версии текста.
- История ограничена 200 действиями и примерно 32 МиБ сохранённого текста на документ. Это ограничивает рост памяти при больших XML.

## Запуск

Распакуйте весь архив в обычную папку и запустите `XRay_UI_Editor.exe`. Рядом должен находиться `XRay_UI_Editor.exe.config`. Visual Studio для запуска не нужна, сетевых запросов программа не выполняет. В комплекте — небольшой искусственный пример; он открывается при первом запуске.

Сборка x64, целевой .NET Framework 3.5. Предназначена для Windows 7 x64 с включённым системным .NET 3.5. При наличии .NET Framework 4.x конфигурация предпочитает его. На Windows 10/11 обычно используется системный .NET 4.x. Проверка сборки и запуска выполняется на Windows Server 2022 / CLR 4; отдельного испытания на Windows 7 не было. Если компоненты .NET отключены, потребуется включить их средствами Windows. Это готовая программа, не установщик и не сборщик исходников.

## Открытие разных вариантов UI

1. Распакуйте архив с XML и текстурами.
2. «Файл → Открыть папку проекта»: выберите папку, внутри которой находятся `config` / `configs` и `textures`.
3. Во вкладке «Файлы» найдите XML и откройте двойным щелчком. Одиночный XML можно открыть через Ctrl+O или перетащить на окно.
4. Для присланных примеров открывайте общий каталог с `config/ui1…ui4` и `textures/ui1…ui4`. Редактор выбирает набор по пути текущего XML, а не по первому совпавшему имени.
5. Для другой структуры папок: «Вид → Папка текстур вручную». Можно также выбрать свой фон DDS / PNG. Архив ZIP сначала нужно распаковать.

Обрабатываются два формата описания атласов: `<ui_texture><file_name>…` и `<w><file name="…"><texture id="…" …/>`. В одном дескрипторе может быть несколько `<file>`: переключение через «Лист атласа». Допускаются XML-фрагменты с несколькими верхними тегами, некавыченные числовые атрибуты и пустые файлы. Некорректный XML открывается как текст для исправления, без выдуманной геометрии.

## Управление

- Клик по элементу: имя, texture id, координаты и область исходного атласа справа.
- Перетаскивание: позиция; восемь белых маркеров: размер. Ctrl+клик: несколько элементов. При перемещении группы сохраняется взаимное положение.
- Колесо: масштаб вокруг указателя. Средняя кнопка или пробел + мышь: панорама.
- Стрелки: 1 единица; Shift+стрелки: 10. Alt при перетаскивании временно отключает привязку. Shift при перемещении ограничивает ось. Esc отменяет текущий жест. F вписывает выделение.
- Ctrl+Z / Ctrl+Y: история. Ctrl+D: дубликат. Кнопка «Удалить» удаляет узел; отмена доступна до закрытия документа.
- Атрибуты справа можно менять, добавлять и удалять. «Размер по ячейкам» вычисляет контейнер по `cell_width × cols_num` и `cell_height × rows_num`.
- Название текстуры редактируется отдельно. Во вкладке «Текстуры» доступны texture id текущего набора. «Показать область в атласе» открывает соответствующий дескриптор.
- Сетка X/Y (1–1024), привязка, линейки, рамки, имена и ячейки включаются независимо. Цвет и частота основных линий доступны в меню «Вид».
- Пропорции 4:3, 16:9, 16:10 меняют просмотр. Координаты XML остаются в исходной виртуальной системе 1024×768. `_16.xml` автоматически получает просмотр 16:9.
- В режиме «АТЛАС» координаты означают пиксели исходной DDS. В режиме «РАЗВЁРСТКА» — положение элементов экрана.
- «Инструменты»: выравнивание группы, проверка координат/подключений, обновление каталога.
- Вкладка XML сохраняет произвольные атрибуты и теги. После ручной правки нажмите Ctrl+Enter. Ошибка не заменяет предыдущую корректную модель.

## Переход с ui_inventory_actor на ui_inventory_actor_ind

Откройте нужный вариант `inventory_new.xml` или `inventory_new_16.xml`. Найдите фон и перейдите к его атласу. В поле «Текстура / файл атласа» укажите `ui\ui_inventory_actor_ind`, проверьте UV-область фона и сохраните дескриптор. Вернитесь к XML развёрстки и передвиньте `dragdrop_*` по новым рамкам. Проверьте ячейки, `fit_cell`, индикаторы и параметры родителей. Координаты 4:3 и `_16` нужно проверять отдельно: редактор не подменяет один файл другим автоматически.

## Сохранение

Ctrl+S сохраняет текущий XML; «Сохранить все» — изменённые документы проекта. Перед перезаписью создаётся соседняя `.bak.<дата>.<суффикс>`. Запись выполняется через временный файл с заменой, с проверкой изменений другими программами. «Сохранить как» создаёт отдельную копию. Редактор сохраняет исходную кодировку, BOM, комментарии, `#include`, пробелы, неизвестные атрибуты; визуальные изменения затрагивают значения нужных атрибутов. Символы, не представимые в исходной кодировке, вызывают ошибку сохранения, а не заменяются на `?`.

Сетка и переключатели запоминаются в `%APPDATA%\XRayUIEditor\settings.xml`. «Сохранить настройки проекта» создаёт `.halk.xml`: настройки вида, пути, родители просмотра, скрытие и блокировки. Эти данные не добавляются в игровые XML. Структурные пути узлов в настройках могут измениться после перестановки или удаления одноимённых элементов.

## Границы предпросмотра

Это редактор геометрии и атласов, а не запущенный X-Ray. Скрипты, локализация, динамический текст, анимации SEQ, шрифтовые таблицы INI и игровые предметы не исполняются. `#include` сохраняется, но не раскрывается в холсте; включённый XML можно открыть отдельно. Для известных экранов инвентаря предусмотрены связи `main`, `bag_static`, полос состояния и некоторых других блоков. В другом UI используйте «Родитель для просмотра» или отключите «Правила инвентаря X-Ray».

Обычные текстуры, UV-области, отражение h/v, оттенок и прозрачность r/g/b/a, а также состояния кнопки `_e`, `_h`, `_t`, `_d` отображаются. Составные рамки и растяжение, которые движок собирает из нескольких фрагментов, могут отличаться. Точное окончательное положение и поведение следует проверить в игре. Внешние XML с неверными закрывающими тегами нужно исправить до визуального редактирования. Редактор не исправляет их автоматически.

DDS: DXT1 / DXT3 / DXT5 (BC1/2/3), A8, RGB16/24/32; DX10 BC1/2/3 и RGBA8/BGRA8. Показывается основной mip-уровень, до 8192 на сторону и 32 млн пикселей. Cubemap, volume, массивы и BC7 не поддерживаются; PNG/BMP/JPEG тоже читаются. Пиксельный редактор и перекраска DDS в эту версию не входят.

## Исходники и сборка

Откройте `UILayoutEditor.csproj` в Visual Studio с компонентами разработки классических приложений .NET или выполните:

```
msbuild UILayoutEditor.csproj /restore /p:Configuration=Release /p:Platform=x64
```

NuGet нужен только при сборке для reference assemblies .NET 3.5. В готовый EXE сторонние runtime-пакеты не входят. Код размещён в отдельной ветке репозитория; пользовательские текстуры и XML туда не включаются.

Проверки: `XRay_UI_Editor.exe --self-test <папка_отчёта>` и `--validate-folder <папка_примеров> <отчёт.txt>`. Второй режим только читает исходные файлы, сравнивает восстановленные байты XML, проверяет изменение/отмену и декодирует DDS.

Справка платформы: [supportedRuntime](https://learn.microsoft.com/en-us/dotnet/framework/configure-apps/file-schema/startup/supportedruntime-element), [reference assemblies .NET 3.5](https://www.nuget.org/packages/Microsoft.NETFramework.ReferenceAssemblies.net35/1.0.3).
